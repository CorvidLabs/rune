# بنية الطرفية الوهمية (PTY) والطرفية (TTY) في Rune

> **دليل للمطوِّرين ولوكلاء الذكاء الاصطناعي**  
> *فهم كيفية إدارة Ruby للطرفيات الوهمية والتدفقات التفاعلية وأتمتة المحثّات في `rune`.*

---

## 1. نظرة عامة: ما الطرفية الوهمية (PTY)؟

عندما يُشغَّل برنامج داخل صَدَفة فرعية عادية أو عبر أنبوب عملية فرعية (مثل `IO.pipe` أو التنفيذ المعتاد في صدفة فرعية)، يُلحِق نظام التشغيل أنابيب قياسية لكلٍّ من `stdin` و`stdout` و`stderr`. وكثير من برامج سطر الأوامر (مثل `git` و`docker` و`python` و`zsh` و`sudo`) تكتشف ما إذا كان `stdout` طرفيةً (باستعمال `isatty()`)، فتُعطِّل الألوان وتنسيق المحثّ أو التخزين المؤقَّت السطري إن لم يكن كذلك.

**الطرفية الوهمية (PTY)** زوجٌ من أجهزة الطرفيات الافتراضية على مستوى نواة النظام، أحدهما رئيسي والآخر تابع:
- **الطرفية التابعة (Slave PTY)**: تُلحَق بالعملية الابنة بوصفها طرفيتها المتحكِّمة (`tty`). فتظنُّ العملية الابنة أنها تعمل داخل طرفية حقيقية (مثل iTerm2 أو xterm).
- **الطرفية الرئيسية (Master PTY)**: يملكها `rune` (عبر `PTYRunner`). يقرأ `rune` مخرجات العملية الابنة ويكتب مُدخلات لوحة المفاتيح مباشرةً في الواصف الرئيسي.

```
+------------------+         Master PTY          Slave PTY         +-------------------+
|  Rune PTYRunner  | <=======================> (Virtual Terminal) <==> |  Child Process    |
| (Agent / Human)  |    (reader / writer IO)                       | (bash, git, etc.) |
+------------------+                                               +-------------------+
```

## 2. تنفيذ PTY في Ruby (`PTY.spawn`)

توفِّر مكتبة Ruby القياسية الوحدة `require 'pty'`. ويستعمل `rune` الدالة `PTY.spawn` داخل `lib/rune/pty_runner.rb`:

```ruby
PTY.spawn(env, command) do |reader, writer, pid|
  # reader: IO object to read output from slave PTY
  # writer: IO object to write stdin into slave PTY
  # pid:    Process ID of child process
end
```

### قراءة الأجزاء دون حجب (`readpartial`)

القراءة السطرية المعتادة (`reader.each_line`) تحجب التنفيذ حتى يصل محرف سطر جديد (`\n`). و**المحثّات التفاعلية** (مثل `Password: ` أو `Select option [y/N]` أو `user@host:~$ `) **لا تنتهي بسطر جديد**. فإن قرأت باستعمال `each_line`، حُجِبت العملية الأب في انتظار `\n`، بينما تظلُّ العملية الابنة منتظرةً مُدخلات المستخدم — فينشأ **تجمُّد متبادل (deadlock)**.

وللقضاء على هذا التجمُّد، يقرأ `rune` المخرجات أجزاءً باستعمال `readpartial(4096)`:

```ruby
loop do
  # Bounded wait rather than a bare readpartial, so signals and the timeout
  # are still serviced while the child is quiet.
  next unless reader.wait_readable(0.2)

  chunk = reader.readpartial(4096)
  output_buffer << chunk
  on_output&.call(chunk) # Real-time streaming callback (NDJSON / TTY)
  script_step_index = process_script_steps(script_step_index, output_buffer, writer) if script
end

# prompt_detected is computed once at the end, from the LAST non-blank line
# only — not "did any line ever look like a prompt". A run that printed a
# prompt and then kept going is not waiting for input, so the any-line form
# answered a question nobody was asking.
prompt_detected = detect_prompt?(output_buffer.lines.reverse.find { |line| !line.strip.empty? })
```

وعندما تنتهي العملية الابنة، تُغلَق الطرفية التابعة، فيرفع `readpartial` الخطأ `Errno::EIO` أو `EOFError`، وهو ما يلتقطه `rune` لينهي عمله بنظافة.

## 3. تنقية ANSI والإخراج المزدوج (للإنسان وللوكيل)

يلتقط `rune` تسلسلات هروب الطرفية ANSI الخام (الألوان وحركات المؤشِّر ومسح الشاشة).

- **للبشر (وضع TTY)**: تُنسَّق المخرجات الخام باستعمال `Renderer.render_tty` بألوان كاملة وتنسيق تفاعلي.
- **لوكلاء الذكاء الاصطناعي (وضع JSON)**: تُمرَّر المخرجات عبر `Parsers::TextSanitizer.strip_ansi(raw_output)` لتجريدها من رموز ANSI، فتُعاد نصًّا نظيفاً يقتصد في رموز نموذج اللغة. ولا يصحُّ هذا على إطلاقه إلا في غياب `--max-output`: فذلك العَلَم يحدُّ الحقلين كلًّا على حدة بالميزانية نفسها، فيصفان عندئذٍ نافذتين مختلفتين من التشغيل، ولا يكون `clean_output` مساوياً لـ `strip_ansi(raw_output)`:

```ruby
# Strips SGR ANSI color codes, cursor escape codes, and terminal controls
ANSI_REGEX = /\e\[[0-9;]*[a-zA-Z]/
clean_output = text.gsub(ANSI_REGEX, '')
```

## 4. منطق اكتشاف المحثّ (`Parsers::PromptDetector`)

لتمييز ما إذا كان الأمر قد انتهى أم أنه واقف عند محثّ تفاعلي، يحلِّل `Parsers::PromptDetector` شُذرات الأسطر المتدفِّقة:

### توقيعات المحثّات المدعومة:
- محثّات الصَدَفة من نوع PS1: `user@host:~$ `، `bash-5.2# `، `➜  rune git:(main)`، `❯ `
- القوائم والاختيارات التفاعلية: `Select:`، `[y/N]`، `(y/n)?`، `Password: `

توقيعان كانت هذه القائمة تدَّعي سابقاً أنهما **لا** يُكتشفان، وقد حُذفا بدل أن يُضافا، لأن تحفُّظ
الكاشف مقصود: `Select an option: ` (نمط السؤال مُثبَّت في موضعه، فهو يطابق `Select:` ولا يطابق جملةً
تنتهي بنقطتين رأسيتين) و`(venv) λ ` (فالمحرف `λ` ليس ضمن صنف محارف المحثّ، وهو `➜ ❯ ›`).

### رفض الإيجابيات الكاذبة:
يتجاهل `PromptDetector` الأسطر التي تحتوي مقارنات برمجية (`if x > 5`) أو إسنادات لمتغيِّرات
الصَدَفة (`export PATH=$PATH`). كذلك يُرفَض اقتباسُ Markdown مثل `> quote`، لكن لأنه لا يطابق أي نمط
إيجابي، لا بقاعدة استثناء — فاستثناء الاقتباس لا ينطلق إلا على سطر يحتوي أيضاً نصاً بين قوسين زاويين.

## 5. محرِّك أتمتة النصوص البرمجية (`Rune::Script`)

يتيح `rune` تعريف نصوص برمجية تفاعلية بلغة DSL لأتمتة برامج PTY متعدِّدة الخطوات:

```ruby
script = Rune::Script.define do
  wait_for(/Select a target environment/)
  send_keys "production\n"
  pause 0.5
  wait_for(/Are you sure\? \[y\/N\]/)
  send_keys "y\n"
end

Rune::PTYRunner.new('deploy-tool', script: script).run
```

يعالج محرِّك النصوص البرمجية الخطوات في مرور واحد غير حاجب، فيكتب `send_keys` مباشرةً إلى `writer` دون انتظار الأجزاء التالية.

## 6. المرور التفاعلي الحي (`PTYWatcher` / `rune watch`)

يخزِّن `PTYRunner` مخرجات الأمر كاملةً في ذاكرة مؤقَّتة ولا يعود إلا بعد انتهائه: وهذا صحيح للبرمجة النصية والالتقاط، لكنه غير صالح حين تجلس فعلاً أمام لوحة المفاتيح تقود برنامجاً تفاعلياً بينما يراقب طرفٌ آخر الجلسة. و`PTYWatcher` (في `lib/rune/pty_watcher.rb`) فئة مستقلة لهذه الحالة الحية ثنائية الاتجاه، لا وضعٌ مُركَّب على `PTYRunner` — فنموذج التنفيذ (وضع الطرفية الخام، وخيط خلفي لتمرير المُدخلات) مختلف بما يكفي لئلَّا ينتمي إلى هناك، ويبقى عقد `PTYRunner` القائل «شغِّل والتقط وعُد مرة واحدة» مجمَّداً كما هو.

### وضع الطرفية الخام (`io/console`)

لكي تصل مفاتيح الأسهم وسائر المُدخلات أحادية البايت أو ذوات تسلسلات الهروب إلى العملية الابنة أصلاً، لا بدَّ أن تغادر الطرفيةُ المتحكِّمة العائدة للعملية *الأب* الوضعَ المطبوخ، حيث تُخزِّن النواة المُدخلات سطراً سطراً وتُظهِر صدى النقرات محلياً حتى يصل سطر جديد. وتُضيف `io/console` (التي يجب استدعاؤها صراحةً، إذ لا تجرُّها `pty` ضمناً) التابعَ `IO#raw`، وهو ما يلفُّ به `PTYWatcher#with_raw_input` جلسة التمرير بأكملها:

```ruby
def with_raw_input(&block)
  entered = false
  @input.raw do
    entered = true
    block.call
  end
rescue Errno::ENOTTY, NoMethodError
  raise if entered   # only fall back if raw-mode *entry* itself failed

  block.call
end
```

لراية `entered` أهميةٌ حقيقية: فمتى انخرط وضع الطرفية الخام انخراطاً فعلياً، وجب أن ينتشر أي استثناء غير ذي صلة يأتي من عمق الجلسة (كمصرِف مخرجات معطوب مثلاً) انتشاراً طبيعياً، لا أن يُعامَل على أنه «وضع الطرفية الخام غير مدعوم» فتُعاد في صمت الجلسةُ المُطلَقة أصلاً كاملةً مرة ثانية.

### التمرير ثنائي الاتجاه

على خلاف حلقة القراءة الواحدة في `PTYRunner`، يُشغِّل `PTYWatcher` أمرين على التوازي: خيطٌ خلفي يمرِّر نقرات المستخدم الحقيقية إلى PTY العملية الابنة فور ورودها (`forward_input`)، بينما يستطلع الخيط الرئيسي مخرجات العملية الابنة ويبثُّها إلى الشاشة فوراً (`pump_output`)، بدل تكديسها في ذاكرة مؤقَّتة لا تُعاد إلا في النهاية.

يفكُّ المساران كلاهما الترميز باستعمال `UTF8StreamDecoder`، الذي يحتفظ باللاحقة الناقصة من ترميز
UTF-8 بين استدعاءات `readpartial`. وبذلك يُصان المحرف متعدِّد البايتات الصحيح حتى حين تشطره النواة
بين جزأين؛ أما التسلسلات المعطوبة حقاً أو الناقصة نهائياً فتظلُّ تتحوَّل إلى محارف استبدال.

كذلك يعكس `PTYWatcher` مقاس الطرفية المتحكِّمة الحالي، صفوفاً وأعمدةً، على PTY العملية الابنة.
وهو يعيد فحصه أثناء حلقة استطلاع المخرجات، فيصل تغيُّر مقاس الطرفية إلى العملية الابنة دون أي عمل
غير آمن داخل مصيدة إشارة.

```
+------------------+   keystrokes    +------------------+   output    +-------------------+
|  Human terminal  | --------------> |  PTYWatcher       | ----------> |  Real terminal      |
|  (raw mode)      |  (bg thread)    |  (master PTY)     |  (live)     |  screen + NDJSON log |
+------------------+                 +------------------+             +-------------------+
```

### سجلّ الأحداث NDJSON

يُكتَب كل جزء يصل إلى الشاشة أيضاً بوصفه حدث NDJSON في ملف سجلّ (وهو افتراضياً ملف مؤقَّت مُعلَن
عنه وآمن من التصادم بأذونات `0600`، أو المسار الذي يحدِّده `--log=PATH`)، فيستطيع وكيل الذكاء
الاصطناعي متابعة الجلسة حيَّةً عبر `tail -f` دون أن تتسرَّب ضوضاء JSON إلى طرفية الإنسان نفسها:

```json
{"event":"start","command":"...","pid":12345}
{"event":"output","bytes":42,"text":"..."}
{"event":"exit","exit_code":0}
```

وليست stderr هي الوجهة الافتراضية، وذلك عن قصد: فـ stderr تتقاسم طرفية الإنسان مع المرور الحي، وقد أظهر الاستعمال الفعلي فوراً أن تشابك JSON مع جلسة تفاعلية يجعلها غير قابلة للقراءة.

وإذا أُغلق مصرِف المخرجات بالخطأ `EPIPE`، يقتل `PTYWatcher` العملية الابنة ويحصد حالتها قبل أن
يُعيد فشلاً منظَّماً، فيمنع بقاء عملية تفاعلية منفصلة حيَّةً بعد انتهاء المراقب.

## 7. معالجة الأخطاء ورموز الخروج

يوحِّد كلٌّ من `PTYRunner` و`PTYWatcher` رموز خروج يونكس عبر الحالات الحدّية:

| الحالة | رمز الخروج | المعالجة |
| :--- | :--- | :--- |
| خروج طبيعي | `status.exitstatus` | إتمام نظيف |
| الأمر غير موجود | `127` | يلتقط `Errno::ENOENT` |
| الإذن مرفوض | `126` | يلتقط `Errno::EACCES` |
| انتهاء مهلة التنفيذ (في `PTYRunner` وحده) | `124` | يلتقط `Timeout::Error`، ثم يقتل العملية الابنة بـ `SIGKILL` ويحصد حالتها — إذ لا يقاطع `Timeout.timeout` إلا مسار التحكُّم الخاص بـ Ruby نفسها، لا عملية نظام التشغيل المُطلَقة |
| قتل العملية الابنة (بإشارة) | `128 + sig` | إشارات مثل `SIGKILL` (137) أو `SIGTERM` (143) |

---

## خلاصة للمطوِّرين

يجمع `rune` بين:
1. `PTY.spawn` لمحاكاة طرفية حقيقية.
2. `readpartial` لقراءة التدفق دون أي تجمُّد متبادل.
3. `UTF8StreamDecoder` مع `TextSanitizer` لإخراج JSON نظيف للوكلاء وآمن عند حدود الأجزاء.
4. `PromptDetector` لفحوص التفاعلية الذكية.
5. لغة `Script` الخاصة (DSL) للإدخال المؤتمت خطوةً خطوة.
6. `PTYWatcher` مع وضع الطرفية الخام من `io/console` لجلسات حية ثنائية الاتجاه يقودها الإنسان، مع سجلّ NDJSON يستطيع الوكيل متابعته بـ `tail`.
